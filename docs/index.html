An operating model for agent skills

Skills, managed
as docs.

Human-readable. Agent-executable. Distributed through Git.

The procedural memory of an agent — how it writes a code review, how it cites literature, how it formats a release — should not live inside a hidden config folder. It should live where the people who own the workflow can read it, review it, version it, and improve it. SkillDocs is a small, deliberately boring pattern for doing exactly that.

§ 01 / PROPOSITION

Skills are operational documents for agents.

SKILL.md should not disappear into a hidden config folder. It should be readable, reviewable, versioned, and improved by the same people who own the workflow.

P · 01

Human-readable

Teams can browse, edit, discuss, and improve skills inside the documentation tools they already trust — Notion, GitBook, VitePress, Obsidian, 飞书, 语雀.

P · 02

Agent-executable

The same Markdown becomes procedural memory an agent installs and uses at runtime. No separate prompt store; the document is the skill.

P · 03

Git-backed

Review, CI, provenance, releases, and rollback bring decades of software-engineering safety into the management of agent behaviour.

§ 02 / EVIDENCE

The ecosystem already shows a management gap.

Public skills are growing quickly, real users are already juggling local folders and installers, and security researchers have found malicious skills in the wild. The answer is not fear; it is visible ownership, review, provenance, and rollback.

§ 03 / PROTOCOL

A closed loop between people and agents.

Every useful correction should become part of the skill library — not another lost chat message. The protocol turns repeated agent coaching into durable team knowledge.

01 Author Write or revise a skill inside a familiar docs surface.
02 Review Sync the Markdown to Git and review the change as a pull request.
03 Verify Run hooks to lint metadata, links, and the generated registry.
04 Distribute Agents pull updated skills from the trusted repository.
05 Improve Failures and corrections become the next skill patch.

§ 05 / ADOPTION

Adopt the pattern before the tooling is complete.

Create a folder. Write clean Markdown. Review changes through Git. Let your agent clients install from the repository. The first CLI milestone will automate the rest.

§ 06 / NON-GOALS

Three things SkillDocs is deliberately not.

Each negation is load-bearing: it keeps the project useful by keeping it small.

not

a marketplace

Public discovery can come later. The first job is helping teams govern their own private skills with confidence.

not

a prompt manager

Skills are filesystem packages and workflow documents, not only runtime prompt templates retrieved by string match.

not

an AI docs generator

The goal is not to make existing docs readable by AI. The goal is to make team procedures installable by agents.
