Improve the docs

Skills are operational docs for agents.

SKILL.md should not disappear into hidden config folders. It should be readable, reviewable, versioned, and improved by the same people who own the workflow.

Human-readable

Teams can browse, edit, discuss, and improve skills in familiar documentation tools.

Agent-executable

The same Markdown becomes procedural memory that agents can install and use.

Git-backed

Review, CI, provenance, releases, and rollback make skill changes safer.

A positive loop between people and agents.

Every useful correction should become part of the skill library, not another lost chat message. The workflow turns repeated agent coaching into durable team knowledge.

  1. 1Write or revise a skill in a docs surface.
  2. 2Sync Markdown to Git and review the change.
  3. 3Run hooks to lint metadata, links, and registry output.
  4. 4Agents update from the trusted repository.
  5. 5Failures become new skill patches.

Clear positioning keeps the project useful.

Not a marketplace

Public discovery can come later. The first job is helping teams govern their own private skills.

Not a prompt manager

Skills are filesystem packages and workflow docs, not only runtime prompt templates.

Not an AI docs generator

The promise is not to make docs readable by AI. It is to make team procedures installable by agents.
